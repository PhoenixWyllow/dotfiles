# Neovim Configuration Migration Notes

This document records the plugin modernization work done in this config, with focus on Mason + LSP and compatibility with recent upstream breaking changes.

## 1) Current State (Before Migration)

The configuration was functional, but several pieces were on APIs or patterns that are deprecated or likely to break with newer plugin versions.

### LSP and Mason

- LSP setup used legacy `require("lspconfig").<server>.setup({ ... })`.
- Mason LSP bridge used old handler flow (`setup_handlers`) and `auto_install` behavior.
- `mason.nvim` and `mason-lspconfig.nvim` used old repository paths (`williamboman/...`).
- Diagnostics options were defined in plugin opts but not applied through `vim.diagnostic.config()` in the LSP config function.

### Plugin Version Strategy

- Telescope was pinned to `branch = "0.1.x"`, which prevents moving to current stable releases.
- Treesitter had no explicit branch pin; with upstream changes, this can accidentally pull incompatible rewrites depending on default branch behavior.

### DAP + Mason

- `mason-nvim-dap` depended on old Mason repo path (`williamboman/mason.nvim`).

## 2) Required Changes (Based on Upstream Breaks)

### nvim-lspconfig (Neovim 0.11+)

- Migrate from legacy `require("lspconfig")` setup calls to modern:
  - `vim.lsp.config("server", opts)`
  - `vim.lsp.enable("server")`

### mason-lspconfig

- Stop using removed/legacy handler-centric setup pattern.
- Use `ensure_installed` for server installation.
- Disable `automatic_enable` when manual per-server config is desired, then explicitly enable each configured server.

### Mason repositories

- Use current repository namespace:
  - `mason-org/mason.nvim`
  - `mason-org/mason-lspconfig.nvim`

### Telescope

- Move from branch pinning (`0.1.x`) to release pinning (`version = "*"`) so Lazy tracks latest stable release tags.

### Treesitter

- Pin compatibility branch intentionally (`master`) for this config to avoid accidental upgrade to an incompatible rewrite track without a full Neovim 0.12 migration plan.

## 3) Implemented Changes

### LSP migration

Updated [lua/plugins/lsp-config.lua](lua/plugins/lsp-config.lua) to:

- Switch Mason plugin repos to `mason-org`.
- Replace old `mason-lspconfig` opts with:
  - `ensure_installed = vim.tbl_keys(servers)`
  - `automatic_enable = false`
- Apply diagnostics with `vim.diagnostic.config(opts.diagnostics)`.
- Replace legacy `require("lspconfig")[server].setup(...)` flow with:
  - `vim.lsp.config(server_name, server_opts)`
  - `vim.lsp.enable(server_name)`
- Keep existing `on_attach`, keymaps, and server-specific settings intact.

### DAP dependency alignment

Updated [lua/plugins/debug.lua](lua/plugins/debug.lua) to use `mason-org/mason.nvim`.

### Telescope update strategy

Updated [lua/plugins/telescope.lua](lua/plugins/telescope.lua):

- From `branch = "0.1.x"`
- To `version = "*"`

### Treesitter safety pin

Updated [lua/plugins/treesitter.lua](lua/plugins/treesitter.lua):

- Added `branch = "master"` for compatibility-focused tracking in this setup.

### Lockfile refresh

Ran `:Lazy sync` headless, which updated plugin commits in [lazy-lock.json](lazy-lock.json).

## 4) Final State (After Migration)

### LSP architecture now

- Mason is the installer/source of truth for server binaries.
- `mason-lspconfig` ensures listed servers are installed.
- Server configuration is handled with modern Neovim LSP API (`vim.lsp.config`).
- Server activation is explicit (`vim.lsp.enable`) for predictable behavior.
- Existing keybindings and buffer-local formatting command are preserved.

### Plugin update posture

- Most plugins are now refreshed in lockfile to latest available commits allowed by specs.
- Telescope is on release-aware pinning.
- Treesitter is deliberately pinned to compatibility branch pending full rewrite migration.

## 5) Mason + LSP Operations

### Add a new LSP server

1. Add a new key in `servers` table in [lua/plugins/lsp-config.lua](lua/plugins/lsp-config.lua).
2. If needed, add `settings`, `filetypes`, or `cmd` under that server.
3. Run `:Lazy sync` (or headless sync) and restart Neovim.

### Remove an LSP server

1. Remove server from `servers` table in [lua/plugins/lsp-config.lua](lua/plugins/lsp-config.lua).
2. Optionally uninstall with `:LspUninstall <server>`.

### Health checks

- `:checkhealth vim.lsp`
- `:checkhealth mason`
- `:LspInfo`
- `:Mason`

## 6) Known Compatibility Notes

- Newer Telescope releases require newer Neovim versions (check `:checkhealth telescope`).
- Treesitter upstream changed significantly; this config intentionally tracks a compatibility branch to avoid forced breakage without full migration planning.

## 7) Maintenance Workflow

1. Update plugins with `:Lazy sync`.
2. Review changes in [lazy-lock.json](lazy-lock.json).
3. Run health checks.
4. Open representative filetypes and confirm:
   - LSP attach
   - completion
   - diagnostics
   - treesitter highlighting
5. If something breaks, consult plugin release notes and adjust spec/config before the next lock update.
